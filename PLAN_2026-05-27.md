## What's wrong and why

### Bug 1: MACD warmup mismatch (primary suspect)

**Location:** `src/consumers/inference_consumer.py`, `BarAccumulator` + `construct_input_tensor`

**What's happening:**

The `BarAccumulator` is created with `maxlen=MIN_BARS` = 60. In `construct_input_tensor`, RSI/MACD/ATR are computed on `closes[-60:]` — i.e., the last 60 bars, which is everything the accumulator holds.

MACD requires **34 bars of warmup** before producing a valid output: EMA-26 converges after 26 bars, the EMA-9 signal line on top of that needs another 8. The `compute_macd_hist` function zero-fills bars 0–33 during warmup (by design, see `src/data/features.py`).

Result: for every inference window, bars 0–33 out of 60 carry `MACD = 0`. That is **57% of the input sequence** with a corrupted feature.

**Why this wasn't a problem in training:**

`src/data/dataset.py` loads the full historical parquet for each stock (hundreds of bars per day, many days), computes RSI/MACD/ATR on the complete series, then slides a 60-bar window across it. Every training window had fully warmed-up MACD because the indicator computation had access to bars 0 through `T` and the window always started well after warmup.

In live inference, we only have 60 bars in the accumulator, so every window starts from bar 0 in warmup territory.

**Evidence that this explains a material chunk of the gap:**

- The 52.65% walk-forward accuracy was measured the same way: full history → sliding windows → warmed-up indicators. The eval script mirrors training exactly.
- The live session accuracy (49.20%) is measured by `overnight_eval.py` which also computes MACD on the full InfluxDB series for each stock — so *the overnight eval does not have this bug*. The 49.20% is what the model achieves when MACD is properly warmed up in post-hoc eval.
- This means the **live inference during the session was worse than 49.20%** because it had the 57%-zeros MACD. The overnight eval is an optimistic measure of live accuracy.
- Closing the warmup gap should move live inference closer to what overnight eval already measures.

**Expected improvement:** Estimated 1–3pp improvement in live directional accuracy. The effect should be most visible in stocks where MACD is a stronger signal (trending stocks like TATASTEEL, JSWSTEEL, TECHM). Stocks where the model already underperforms (ONGC, POWERGRID, RELIANCE) may be driven by other factors.

### Bug 2: Overnight eval uses zeros for Nifty50 (secondary, eval-only)

**Location:** `scripts/overnight_eval.py`, `build_feature_matrix()`

**What's happening:**

The TFT model expects col 10 of `past_inputs` to be the Nifty50 index 1-minute log return. During live inference, the `InferenceConsumer` correctly routes Nifty50 ticks (token 256265) to `self.nifty_acc` and fills col 10 with real data.

But `overnight_eval.py` queries InfluxDB, which doesn't store Nifty50 separately by a known symbol key. So the eval script hardcodes `nifty_col = np.zeros(n)`:

```python
nifty_col = np.zeros(n, dtype=np.float64)   # overnight_eval.py line ~151
```

**Why this creates a discrepancy:**

The 49.20% figure from overnight eval was measured with col 10 = 0. Real live inference had col 10 = actual Nifty50 returns. These are not the same input distribution the model saw. The overnight eval therefore underestimates true live accuracy by a small but nonzero amount. Best estimate: **0.5–1pp optimism error** in the negative direction (eval is pessimistic vs live).

This doesn't need fixing immediately (49.20% is already a useful floor estimate), but it means tomorrow's comparison will still carry this error.

## The plan: three tasks before 9:15 AM IST

### Task 1 — Fix MACD warmup in `inference_consumer.py`

**Why it's pre-market:** If done during market hours, it requires restarting the consumer and losing the warm-start bars (inference resumes from parquet reload, which adds ~2min delay per stock). Pre-market restart is free.

**Change 1: Expand BarAccumulator maxlen from 60 to 100**

In `InferenceConsumer.__init__` (line ~135):
```python
# Before:
self.nifty_acc = BarAccumulator(maxlen=MIN_BARS)

# After:
self.nifty_acc = BarAccumulator(maxlen=MIN_BARS + 40)
```

In `consume()` where per-stock accumulators are created (line ~432):
```python
# Before:
acc = BarAccumulator(maxlen=MIN_BARS)

# After:
acc = BarAccumulator(maxlen=MIN_BARS + 40)
```

**Rationale:** With maxlen=100, the accumulator holds the last 100 completed bars. MACD computed on 100 bars is fully warmed up for all 60 values in the inference window. Cost: ~40 extra bar dicts per stock in memory. At ~200 bytes/dict × 40 extra × 48 stocks = ~400KB. Negligible.

---

**Change 2: Load more warm-start bars from parquet**

In `_warm_start_from_parquet` (line ~365):
```python
# Before:
df = df.tail(MIN_BARS + 5)

# After:
df = df.tail(MIN_BARS + 45)
```

**Rationale:** With maxlen=100 but only 65 bars loaded from parquet, the accumulator starts the session with only 65 historical bars — enough for RSI and ATR warmup (14 bars each), but MACD still has 34-bar zeros for the oldest part of the preloaded window. Loading 105 bars ensures that even bar 0 of the live session can draw on 105 historical bars for MACD, meaning MACD is fully warmed up immediately.

---

**Change 3: Compute indicators on all available bars, not just last 60**

In `construct_input_tensor`, currently:
```python
closes = np.array([b["close"] for b in bars], dtype=np.float64)[-MIN_BARS:]
highs  = np.array([b["high"]  for b in bars], dtype=np.float64)[-MIN_BARS:]
lows   = np.array([b["low"]   for b in bars], dtype=np.float64)[-MIN_BARS:]

rsi_vals  = compute_rsi(closes).astype(np.float32)[-MIN_BARS:]
macd_vals = compute_macd_hist(closes).astype(np.float32)[-MIN_BARS:]
atr_vals  = compute_atr(highs, lows, closes).astype(np.float32)[-MIN_BARS:]
```

Change to pull all available bars from the accumulator before slicing:
```python
all_bars   = acc.get_bars()                                          # up to 101 bars
all_closes = np.array([b["close"] for b in all_bars], dtype=np.float64)
all_highs  = np.array([b["high"]  for b in all_bars], dtype=np.float64)
all_lows   = np.array([b["low"]   for b in all_bars], dtype=np.float64)

rsi_vals   = compute_rsi(all_closes).astype(np.float32)[-MIN_BARS:]
macd_vals  = compute_macd_hist(all_closes).astype(np.float32)[-MIN_BARS:]
atr_vals   = compute_atr(all_highs, all_lows, all_closes).astype(np.float32)[-MIN_BARS:]
```

The price-return features (cols 0–6) continue to use the last 61 bars as before — this change only affects the three indicator columns (7, 8, 9).

**Rationale:** Even with maxlen=100, if we pass only 60 bars to `compute_macd_hist`, we get the same zero-fill problem. The fix requires both the larger buffer (Changes 1+2) AND computing indicators on all of it (Change 3). All three changes together are necessary and sufficient.
